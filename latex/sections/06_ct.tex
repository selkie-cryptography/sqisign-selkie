\section{Constant-Time Considerations}
\label{sec:ct}

\subsection{The spec's silence on side channels}

The SQIsign specification analyzes \texttt{SuitableIdeals} only in
terms of failure probability (\S9.3.2), not side-channel resistance.
By tracing Algorithm~4.2 (signing), we confirmed that the quaternion
algorithms operate on data derived from the secret key
$I_{\mathrm{sk}}$ (lines~13--19).  The variable-time behavior of the
C reference is a pragmatic gap, not a deliberate security argument.

\subsection{Published CT techniques}

Seven papers form a complete constant-time stack for SQIsign~v2:
\begin{itemize}
  \item Kouider et al.~\cite{EPRINT:KMJK25} provide constant-time big
    integer arithmetic (division, exponentiation, square root) up to
    ${\sim}12{,}000$~bits.
  \item Hanyecz et al.~\cite{EPRINT:HKKKS25} give the first constant-time
    LLL-like lattice reduction for dimension~4, replacing the
    variable-time L2 algorithm used in \texttt{SuitableIdeals}.
  \item Basso et al.~\cite{basso2025} cover CT~HNF, CT
    \texttt{IdealGenerator}, and CT \texttt{RepresentInteger}---the
    three core quaternion subroutines.
  \item Kim et al.~\cite{EPRINT:KLKL25} prove explicit worst-case size
    bounds for all quaternion intermediates in Round-2 SQIsign,
    enabling fixed-precision (no multi-precision) arithmetic.
  \item Mukherjee et al.~\cite{EPRINT:MCJKR25} and Jacquemin et
    al.~\cite{EPRINT:JMKR23} demonstrate and propose mitigations for
    SPA attacks on Cornacchia's algorithm---the most urgent
    constant-time target.
\end{itemize}

\subsection{Current status}

Signing and key generation are \textbf{not yet constant-time.}  The
entire quaternion arithmetic layer---lattice reduction (L2/LLL), Hermite
Normal Form, Cornacchia/\textsc{RepresentInteger}, and
\textsc{IdealToIsogeny}---is variable-time on secret-derived data.
Each identified variable-time code path on a secret-derived input
carries a \texttt{TODO(ct)} marker citing the Algorithm~4.2 line that
makes the input secret-derived; the marker set is the in-tree
inventory of work the CT pass must close.

Field arithmetic (\S\ref{sec:arch}), curve operations, and
verification are constant-time or operate on purely public data.

End-to-end interoperability against the C reference is complete
(\S\ref{sec:status}); constant-time hardening is the active
workstream, and \S\ref{sec:post-baseline} logs each landed and
tried-rejected step.

\subsection{Leaks beyond the tagged set}

The \texttt{TODO(ct)} inventory above captures the quaternion-layer
paths the implementer already knew were variable-time.  A focused
audit of the deuring layer and the underlying bigint arithmetic
surfaced three additional findings the inventory had missed: two
undocumented CT leaks on the sign-side secret path, plus one
adjacent correctness violation.

\paragraph{\texttt{BigInt::two\_adic\_val} variable-time leak.}
The function is documented as constant-time and is called on
secret-derived inputs in \textsc{SuitableIdeals} (the dyadic
valuation of $\gcd(u, v)$).  The body dispatched
\texttt{if limb == 0 \{ 64 \} else \{ limb.trailing\_zeros() \}}
per limb~--- the \texttt{else} branch invokes the variable-time
\texttt{u64::trailing\_zeros} intrinsic, and the
\texttt{if limb == 0} test itself is a data-dependent branch.
Both leak the limb's value.  A CT helper
(\texttt{super::trailing\_zeros}) was already present in the same
module and returns \texttt{64} for zero by construction; swapping
the dispatch for an unconditional call closes both the branch and
the variable-time intrinsic in a one-line fix.

\paragraph{\texttt{compute\_even\_response} parity branch.}
The body of \texttt{deuring::compute\_even\_response}~--- called
in signing on the secret response quaternion~$\alpha$~--- branches
on the parity of $\gcd(s_0, t_0)$, where $(s_0, t_0)$ are
$\alpha$-derived matrix entries.  Both the \texttt{gcd} call and
the parity branch leak bits about $\alpha$.  The
\texttt{gcd} is variable-time by design (Stein's binary GCD,
explicitly marked); the parity branch was undocumented.  We
tagged the function with a \texttt{TODO(ct)} marker matching
the other ${\sim}18$ such markers in the crate and noted
the eventual fix shape (always evaluate both columns, select
via \texttt{ConditionallySelectable}, with a CT GCD once one
is available).

\paragraph{\texttt{BigInt::wrapping\_neg} invariant violation.}
A correctness-class finding adjacent to the CT audit:
\texttt{wrapping\_neg} produced the invalid form
\texttt{\{sign: 1, limbs: [0; N]\}} on zero input, violating the
documented canonical-zero invariant.  The malformed zero was
masked by downstream guards (\texttt{is\_negative} and
equality both \texttt{\&}-gate by \texttt{mag\_is\_zero}), but
the four direct \texttt{self.sign == 1} checks in
\texttt{gcd.rs} would have treated it as negative.  Fixed by
masking the post-XOR sign bit by \texttt{(1 - is\_zero)} in
constant time.
