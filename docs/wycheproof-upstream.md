# Upstreaming SQIsign vectors to C2SP/wycheproof

This doc tracks the plan for contributing `tests/vectors/sqisign_*.json`
to [C2SP/wycheproof](https://github.com/C2SP/wycheproof) as the first
SQIsign test-vector set in that suite.

## Status

The four files under `tests/vectors/` are upstream-ready in content:

| File | Tests | Provenance |
|---|---|---|
| `sqisign_verify.json` | 54 | invalid: independently generated here (perturbation); valid: deterministic KAT outputs from fixed seeds, sourced from the SQIsign C reference's KAT release |
| `sqisign_verify_extended.json` | 24+ | invalid: generated by `tests/wycheproof.rs::generate_extended_vectors`; valid (cross-order): KAT outputs from fixed seeds |
| `sqisign_keygen.json` | 14 | invalid: perturbation; valid: deterministic KAT outputs |
| `sqisign_sign.json` | 1 | valid: deterministic KAT output |

Valid vectors are **spec-derived KATs**, not C-ref-locked. Any
conformant implementation that matches the reference's canonical-form
choices (Montgomery model normalization, theta splitting index
conventions) will produce byte-identical KATs from the same seeds —
selkie itself does, and that byte-equality is what the lib's
`sign_kat_derand_*` tests assert.

## What "ready" means

- **JSON format**: matches the C2SP/wycheproof schema convention —
  `algorithm`, `schema`, `generatorVersion`, `numberOfTests`,
  `header`, `notes`, `testGroups[].tests[]` with `tcId`, `comment`,
  `result`, `flags`. Verified by `cargo test --test wycheproof`.
- **Metadata stamped**: `generatorVersion: "sqisign-selkie-0.0.1"`
  on all four files; per-group `type` populated.
- **JSON encoding hygiene**: vectors are generated with literal
  characters, not HTML-escaped (per the vector-forge skill's
  `lessons-learned.md` §14 — Go's `json.Marshal` silently escapes
  `>`/`<`/`&`; selkie's generator hand-writes JSON so the issue
  doesn't apply).
- **Cross-impl verification**: the valid KAT vectors verify on the C
  reference (definitionally — they came from its KAT file) and on
  selkie (`sign_kat_derand_*` lib tests). The invalid vectors are
  rejected by selkie (the wycheproof harness asserts this); they are
  expected to be rejected by the C reference as well, but that has
  not been mechanically verified per-vector. Mechanical check before
  upstream: regenerate the invalid set against `the-sqisign`'s verify
  harness and confirm every `result: "invalid"` vector is rejected.

## What needs to happen for actual upstream

1. **Choose a target directory layout.** C2SP/wycheproof groups
   files under `testvectors_v1/` (current) or `testvectors/` (legacy).
   SQIsign would land as `testvectors_v1/sqisign_*_test.json`.
   Filenames may need to adjust to match the suite's convention
   (`sqisign_verify_test.json` vs current `sqisign_verify.json`).

2. **Land a JSON schema.** C2SP/wycheproof publishes per-algorithm
   schemas under `schemas/`. Need to author
   `schemas/sqisign_verify_schema.json`, `…_keygen_schema.json`,
   `…_sign_schema.json` matching the JSON shapes selkie emits.
   The `schema` key in each vector file already points at these
   filenames; once the schemas land upstream the references resolve.

3. **Run the upstream's existing test consumers.** C2SP/wycheproof
   maintains language-specific consumers (e.g. for Go, Python) that
   parse every vector file and assert basic shape. SQIsign vectors
   need to pass those.

4. **Open the PR.** Target: `C2SP/wycheproof:main`. Single PR adding:
   - `testvectors_v1/sqisign_*.json` (4 files)
   - `schemas/sqisign_*_schema.json` (3 schemas)
   - Notes in the project README about the new algorithm.

5. **Mechanical cross-impl pass before submission.** Run the invalid
   vector set against the C reference's verify harness; confirm
   100% rejection. This is the property the wycheproof PR will
   advertise; getting it wrong means the PR gets bounced. The
   selkie wycheproof harness already does this on selkie; replicate
   on the-sqisign before submission.
